How the lifecycle works ↗
RUNNING

Doing the work.

A Firecracker process runs your Linux environment. Requests and active sessions keep it awake.

After 30 seconds idle →
WARM

Holding your place.

Memory is saved to disk. Processes freeze, then resume when the next request arrives.

After the warm TTL (default: 1 hour) →
COLD

Keeping your files.

Only the disk remains. The next request boots a fresh VM with your filesystem intact.

BRING YOUR OWN HARDWARE

Your little cloud
starts here.

You’ll need Linux, read/write access to /dev/kvm, Go, and rootless Podman.

The daemon runs as your user. Guest networking is an optional host setup step.

Read the host setup guide ↗
01 / INSTALL & START
git clone https://github.com/jhgaylor/wisp
cd wisp
make deps image
make install-service
02 / CONNECT YOUR CLI
export SPRITES_API_URL=http://127.0.0.1:7788
export SPRITE_TOKEN=$(cat ~/.local/share/wisp/token)

sprite create dev
sprite exec -s dev -- uname -a

Already have the official sprite CLI? You’re ready.
Or connect with the Python, JavaScript, or Go SDK.
